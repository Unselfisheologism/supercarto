The GTFS load path is columnar: zip entries stream one at a time and stop_times go straight into per-trip arrays (no row objects, ids interned, sorted via one index permutation). Wire semantics unchanged — the TypeScript suite (461) and the parity gate pass.

Verified live on Translink SEQ (35 MB zip): the departure-board query that previously OOMed on Node's default heap now answers on a 512 MB heap, byte-identical, and the realtime join holds at scale (757 trip predictions joined, feed 32 s old, live delay lines on the boards).
